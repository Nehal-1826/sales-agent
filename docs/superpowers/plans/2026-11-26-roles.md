# Changing Roles (and Choosing Super Admin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** A super admin changes any account's role from the console's Users page — Member, Admin, Owner or Super admin — with a reason, and the server refuses every change that would leave a company without an owner or the console without a super admin.

**Architecture:** One module holds the rules (`core/roles.py`), called by one platform endpoint. "Super admin" stays what it is today — an account with no workspace and `is_staff` — so choosing it moves the account out of its company and choosing a company role for it moves it into one. The warmup service keeps its own copy of each person with its own role; it gets one new door to change that role, and Django tells it first (nothing changes when it cannot be reached).

**Tech Stack:** Django + DRF, FastAPI (warmup service), React + TypeScript, pytest, Playwright.

Spec: `docs/superpowers/specs/2026-11-26-roles-design.md`.

## Global Constraints

- Only a platform admin (OTP-satisfied) may change a role; every change needs a reason and is written to `PlatformAuditLog` as `platform.user.role`.
- Rows are changed with `QuerySet.update()`, never `user.save()` — `save()` re-attaches the active workspace to an account that has none.
- The warmup service is asked FIRST; when it cannot be reached, nothing changes (`502 warmup_unavailable`, detail starting "Nothing was changed.").
- The warmup rule "signing in never flips an existing copy's role" stays, and so do its tests.
- Plain, everyday words in every message. The console says "Super admin", not "Platform admin", where it names the role; identifiers (`platform_admin`, `is_platform_admin`) do not change.
- No new dependencies. No push, no deploy.
- Tests never send e-mail and never call the real warmup service (`core.warmup_accounts` is patched in the Django tests).

## Contract

| Call | Body | Answer |
|------|------|--------|
| `POST /api/platform/users/<id>/role/` | `{role: 'member'\|'admin'\|'owner'\|'super_admin', reason: string, workspace?: number}` | 200 `{changed: true, from, to, workspace_left: {id, name, slug} \| null, workspace_joined: {id, name, slug} \| null}` |
| `GET /api/platform/workspaces/` | — | 200 `[{id, name}]` — the running companies, by name |
| `POST /api/admin/users/{user_id}/role` (warmup service) | `{role: 'client'\|'super_admin'}` | 204 |

Errors of the first call: `400 {error}` with `reason_required`, `bad_role`,
`cannot_change_role`, `already_has_role`, `no_email`, `last_owner`,
`workspace_required`, `workspace_stopped`, `last_super_admin`, `seat_limit`;
`404 not_found`; `502 | 503 warmup_unavailable`.

```python
class AdminRoleBody(BaseModel):
    role: Literal["client", "super_admin"]


@router.post("/users/{user_id}/role", status_code=204)
async def set_user_role(
    user_id: str,
    payload: AdminRoleBody,
    session: Annotated[AsyncSession, Depends(get_db)],
    actor: Annotated[User, Depends(require_super_admin)],
) -> None:
    """Change the role of an existing account (super_admin only).

    Signing in through the bridge never flips the role of an existing row
    (app.api.deps._provision_bridge_user) — this is the one door that does,
    and only the main system uses it (core.roles: a super admin changed the
    account's role in the console)."""
    target = (
        await session.execute(select(User).where(User.id == _as_uuid(user_id)))
    ).scalar_one_or_none()
    if target is None:
        raise HTTPException(status_code=404, detail="User not found")
    if target.id == actor.id:
        raise HTTPException(status_code=400, detail="You cannot change your own role")
    target.role = UserRole(payload.role)
    await session.commit()
```

```python
def set_role(email, admin, role):
    """Give every copy of this e-mail address `role` ('client' or
    'super_admin') on the warmup side. Returns how many were told."""
    copies = copies_for(email, admin)
    for copy in copies:
        resp = _call(admin, 'POST', f"/api/admin/users/{copy.get('id')}/role", json={'role': role})
        if resp.status_code != 204:
            raise WarmupAccountsError('The warmup service did not change the account role.')
    return len(copies)
```

```python
"""Change a person's role — Member, Admin, Owner or Super admin (the console).

A platform admin does this from the console (billing.views_platform.user_role).
"Super admin" is not a role value: it is an account with no workspace and
is_staff set (core.authz.is_platform_admin). Choosing it takes the account out
of its company; choosing a company role for a Super admin puts it into one.

Two things are never left behind: a company always keeps an owner (only
owners can pay) and the console always keeps a super admin. The warmup
service keeps its own copy of each person with its own role: it is told
FIRST, and when it cannot be reached nothing changes."""

import logging

from django.db import transaction
from django.utils import timezone

from . import warmup_accounts
from .authz import is_platform_admin
from .models import ImpersonationTicket, User, Workspace

log = logging.getLogger(__name__)

SUPER_ADMIN = 'super_admin'
WORKSPACE_ROLES = ('member', 'admin', 'owner')
ALL_ROLES = WORKSPACE_ROLES + (SUPER_ADMIN,)

WORDS = {'member': 'Member', 'admin': 'Admin', 'owner': 'Owner', SUPER_ADMIN: 'Super admin'}


def label(role):
    return WORDS[role]


def role_of(user):
    """The role the console shows for an account."""
    return SUPER_ADMIN if is_platform_admin(user) else user.role


def _name(user):
    return user.get_full_name() or user.username


def _owners(ws, without=None):
    qs = User.objects.filter(workspace=ws, role='owner', is_active=True, deleted_at__isnull=True)
    return qs if without is None else qs.exclude(pk=without.pk)


def _another_super_admin(than):
    return User.objects.filter(workspace__isnull=True, is_staff=True, is_active=True).exclude(pk=than.pk).exists()


def can_change(admin, target, role, workspace=None):
    """(error, detail, status) when `admin` may not make `target` `role`, else None."""
    if target is None:
        return 'not_found', 'No such account.', 404
    if role not in ALL_ROLES:
        return 'bad_role', 'Unknown role.', 400
    if target.pk == admin.pk:
        return 'cannot_change_role', 'You cannot change your own role.', 400
    if target.deleted_at is not None:
        return 'cannot_change_role', 'This account is deleted. Restore it first.', 400
    was, company = role_of(target), target.workspace
    if role == was:
        return 'already_has_role', f'This account is already {label(role).lower()}.', 400

    if role == SUPER_ADMIN:
        if not (target.email or '').strip():
            return 'no_email', 'A super admin needs an e-mail address on the account.', 400
        # leaving the company: an owner must stay (only owners can pay)
        return _keeps_an_owner(company, target) if company is not None else None

    # a company role. Leaving a Super admin (or a company-less account) needs a company to join
    if company is None:
        if workspace is None:
            return 'workspace_required', 'Choose the company this account joins.', 400
        if not workspace.is_active:
            return 'workspace_stopped', f'{workspace.name} is stopped.', 400
        if was == SUPER_ADMIN and not _another_super_admin(target):
            return 'last_super_admin', 'At least one super admin must remain.', 400
        from billing.entitlements import BillingError, check, has_paid_access
        if has_paid_access(workspace):
            try:
                check(workspace, 'seats', add=1)
            except BillingError:
                return 'seat_limit', f'The {workspace.name} plan has no seat left.', 400
        return None

    # inside the same company: an owner must stay
    if was == 'owner':
        return _keeps_an_owner(company, target)
    if was == 'admin' and role == 'member' and not _owners(company).exists():
        return 'last_owner', f'Nobody would be left to run {company.name}. Make someone else owner first.', 400
    return None


def _keeps_an_owner(company, without):
    if _owners(company, without=without).exists():
        return None
    return 'last_owner', f'{_name(without)} is the only owner of {company.name}. Make someone else owner first.', 400


def _onboarding(target, workspace):
    """The onboarding state to store when the account becomes an Owner or an
    Admin. A set-up company's wizard is not theirs to finish — its finish
    switches the company's autopilot on or off — so they are marked done. A
    company that is not set up yet is left alone: somebody has to."""
    from .models import AppSettings
    set_up = AppSettings.all_tenants.filter(workspace=workspace).exclude(company_name='').exists()
    if not set_up:
        return target.onboarding
    return {**(target.onboarding or {}), 'done': True}


def change_role(admin, target, role, reason=None, workspace=None, ip=None):
    """Make `target` `role`. Returns {'from', 'to', 'workspace_left', 'workspace_joined'}."""
    was, left = role_of(target), target.workspace
    email = target.email or ''
    now = timezone.now()

    # 1. the warmup service first: when it cannot answer, nothing below runs
    if role == SUPER_ADMIN:
        warmup_accounts.set_paused(email, admin, True)        # while its copy is still a client
        warmup_accounts.set_role(email, admin, 'super_admin')
    elif was == SUPER_ADMIN:
        warmup_accounts.set_role(email, admin, 'client')
        warmup_accounts.set_paused(email, admin, False)      # what the promotion paused runs again

    # 2. the account
    if role == SUPER_ADMIN:
        with transaction.atomic():
            User.objects.filter(pk=target.pk).update(workspace=None, is_staff=True)
            ImpersonationTicket.objects.filter(target=target, ended_at__isnull=True).update(ended_at=now)
    else:
        fields = {'workspace': workspace, 'role': role, 'is_staff': False, 'is_superuser': False}
        if role in ('owner', 'admin'):
            fields['onboarding'] = _onboarding(target, workspace)
        with transaction.atomic():
            User.objects.filter(pk=target.pk).update(**fields)

    # 3. the record
    from billing.payments import audit
    place = lambda w: {'id': w.pk, 'name': w.name, 'slug': w.slug} if w else None
    audit('platform.user.role', left if role == SUPER_ADMIN else workspace,
          {'target_user_id': target.pk, 'target_email': target.email, 'target_username': target.username,
           'from': was, 'to': role, 'reason': reason,
           'workspace_left': place(left) if role == SUPER_ADMIN else None,
           'workspace_joined': place(workspace) if was == SUPER_ADMIN else None},
          actor=admin, ip=ip)
    return {'from': was, 'to': role,
            'workspace_left': place(left) if role == SUPER_ADMIN else None,
            'workspace_joined': place(workspace) if was == SUPER_ADMIN else None}
```

## As built (26 Nov 2026)

Done as planned, with these differences — each one found by a test or the gate:

- **A real bug, caught by the tests.** For a role change *inside* a company the
  request's `workspace` is empty (it is only sent when a company is joined),
  and `change_role` wrote that empty value: the account was quietly taken out
  of its company. It now works out where the account is afterwards (`home`):
  the joined company from outside, its own company otherwise. Its own test:
  `test_a_change_inside_a_company_leaves_the_person_in_it`.
- **The first account of a company is always made its owner** (an existing
  model rule). Several tests that meant to create a Member had created a
  second Owner; they now create an owner first
  (`company_with_owner`), and so does the gate.
- **A gate check that asks the server for a refusal must look at the state
  first.** In another state the same request is a real change — one run made
  the throwaway Member a Super admin that way. The look now sends nothing
  unless the accounts are as the looks before left them.
- **The rail's foot names the signed-in account.** It was a hard-coded
  "Platform Admin"; with several Super admins possible and nobody able to
  change their own role, it now shows the account's name (`PlatformShell`).
- The dialog says "an Admin" / "an Owner" (the spec's literal "a {role}"
  would read "a Admin"); an account in no company that is made a Super admin
  reads "This makes {name} a Super admin." instead of a sentence about leaving
