System Architecture

How every component connects — from user signup to inbox reputation scoring

⚛

React Dashboard

User connects email via OAuth (Google Workspace) or SMTP/IMAP creds. Dashboard shows real-time warmup progress, inbox placement score, daily volume graph, and reputation health.

React + Vite Zustand Recharts TailwindCSS
⚙

FastAPI Backend

REST API handles auth, mailbox CRUD, warmup config, analytics. JWT auth + API key for external integrations. Rate limiting per tenant. WebSocket for live warmup feed.

FastAPI SQLAlchemy Pydantic v2 JWT
⚡

Warmup Scheduler Engine

Core brain. Celery Beat schedules warmup tasks per mailbox. Gradual ramp algorithm: Day 1 = 5 emails, increases by 3-5/day until target (50-100/day). Distributes sends evenly across Gmail, Outlook, Yahoo network inboxes.

Celery Redis Celery Beat APScheduler
✉

SMTP/IMAP Worker Pool

Celery workers send warmup emails via user's SMTP and read responses via IMAP. Actions: send, open, reply, star, move-from-spam, mark-important. Each action mimics human timing (random 30s-5min delays).

aiosmtplib aioimaplib Celery Workers
🌐

Peer Inbox Network (The Moat)

This is the hardest and most critical piece. A pool of 1000+ real email inboxes (Google Workspace, Office365, Yahoo) that your system controls. These inboxes receive warmup emails, open them, reply positively, star them, and rescue from spam. Quality of this network = quality of your product. Start with 200-500 inboxes, scale as revenue grows.

Google Workspace Accounts Office365 Accounts Yahoo Accounts IMAP Listeners Auto-Responder Bots
📈

Reputation Scoring Engine

Pulls data from Google Postmaster Tools API, Microsoft SNDS, MXToolbox blacklist checks. Computes composite "Warmth Score" (0-100) from: inbox placement %, spam rate, bounce rate, engagement signals. Alerts on drops.

Postmaster API SNDS API Blacklist Checks
✎

AI Content Generator

Generates realistic warmup email content — business conversations, meeting follow-ups, project discussions. No marketing language. Rotates topics, signatures, greetings. Uses Claude API or local LLM to keep content unique per thread.

Claude API Template Engine Content Rotation
🔒

DNS & Auth Validator

On mailbox connect, auto-checks SPF, DKIM, DMARC records. Flags misconfigurations before warmup starts. Continuous monitoring — alerts if DNS records break. This prevents wasted warmup on broken setups.

dnspython checkdmarc SPF/DKIM Validator
🗃

PostgreSQL + Redis

PostgreSQL stores users, mailboxes, warmup configs, daily metrics, peer network state. Redis handles Celery task queue, rate limiting counters, real-time warmup status cache, and WebSocket pub/sub for live dashboard updates.

PostgreSQL 16 Redis 7 TimescaleDB (metrics) Connection Pooling

💡 Key Insight

The peer inbox network is your moat. Everything else (dashboard, scheduler, scoring) is commodity code any dev can build. The network of high-reputation inboxes that interact with your users' emails is what makes or breaks the product. Budget $500-1500/month for maintaining 500-1000 Google Workspace + Office365 accounts.

RAMP-UP ALGORITHM

Day 01-03:  5 emails/day  (build initial trust)
Day 04-07: 10 emails/day  (monitor bounce/spam)
Day 08-14: 20 emails/day  (check Postmaster data)
Day 15-21: 35 emails/day  (steady ramp)
Day 22-28: 50 emails/day  (target cruise speed)
Day 29+:   50-100/day   (maintain + outreach blend)

💡 Critical Detail

Both inbound AND outbound cycles matter. ESPs look at bidirectional engagement — your inbox should both send and receive real conversations. The spam-rescue action (moving email from spam to inbox) is the highest-signal positive engagement you can generate.

💡 Deploy Pattern

Same VPS, separate systemd services. warmpulse-api on port 8001, sasha-api stays on 8000. Nginx reverse proxy routes /warmpulse/* to 8001. Shared PostgreSQL server, separate database. Redis shared instance with key prefix namespacing.

💡 Index Strategy

Composite index on warmup_logs(mailbox_id, created_at DESC) for dashboard queries. Partial index on peer_inboxes WHERE is_active=true for scheduler pairing. daily_metrics gets a UNIQUE constraint on (mailbox_id, date) for upsert patterns.

MVP Roadmap

8-week plan to launch a working warmup tool

Week 1-2

Foundation + Peer Network Setup

Set up PostgreSQL schema, FastAPI project structure (copy SashaLMS patterns), user auth with JWT. Most importantly: purchase 50-100 Google Workspace accounts across 10-15 domains. Set up SPF/DKIM/DMARC on all. This is your seed peer network. Cost: ~$300-600/month for Google Workspace.

Week 3-4

Warmup Engine Core

Build Celery + Redis task queue. Implement SMTP send worker + IMAP listener. Build the ramp-up algorithm (day-based volume scaling). Wire peer inboxes as auto-responders (open, reply, star, spam-rescue). Test with your own email first — verify inbox placement improves.

Week 5-6

Dashboard + DNS Validator

React dashboard: mailbox connect flow (SMTP/IMAP creds input + OAuth), warmup progress chart, daily metrics table. DNS checker on connect — auto-validate SPF/DKIM/DMARC and show fix instructions. Warmth Score display with color-coded health indicator.

Week 7

AI Content + Content Rotation

Integrate Claude API for generating unique warmup email threads. Build 50+ template variations as fallback. Implement thread continuation (warmup emails form realistic multi-reply conversations, not isolated one-offs).

Week 8

Deploy + Beta Launch

Deploy on Hostinger VPS alongside SashaLMS. systemd services: warmpulse-api, warmpulse-worker, warmpulse-beat. Nginx routing. Launch to 10-20 beta users (cold outreach agencies in India). Iterate based on actual deliverability data.

💡 Reality Check

Weeks 1-2 (peer network) is the make-or-break step. Don't skip it. Without real Google Workspace and Office365 inboxes in your network, the warmup signals won't be trusted by ESPs. Start with 50 inboxes, grow to 500+ as you get paying customers. Budget: ~$500/mo initially for the network infrastructure.
